- Python stdlib + SQLite ingestion/query/routing/API boundaries remain intact.
  Schema has namespaced stops/routes, trips/times, calendars/exceptions, shapes and
  transfers. Tests cover synthetic transfer, street, pack and golden-routing cases.
- Kotlin native router, street graph, planner/stop map and their tests are present.
  Older README/agent architecture summaries describing only an Android shell are
  historical; passing JVM tests do not establish complete offline functionality.
- Termux TUI uses curses and fixed commands. The new Crostini interface reuses the
  Crostini shell command policy, without rewriting the Termux implementation.
- Pack exporter and catalogue validator exist. Transit data was not downloaded or
  modified. Fixture reports of missing Hartford/PVTA are synthetic test output,
  not a new assessment of real installed coverage.
- Existing CI runs Python tests and Android build/JVM tests, with a debug APK
  artifact upload. Remote CI for this new work has not been verified.
- Open PR inventory included draft #37 Crostini and #38 Termux TUI plus earlier
  stacked Android/Termux proposals. No branch was blindly cherry-picked or merged.
- Source-version retention, reviewed PDF activation, authoritative missing-feed
  acquisition, offline basemap and physical airplane-mode acceptance remain open.
  Do not expand geography at the expense of these correctness gates.
