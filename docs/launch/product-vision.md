# Product vision: a regional transit network you can explore

**Working reference:** The user describes the intended feeling as "trains.fyi, but for regional transit." This is a conceptual inspiration, **not** permission to copy its interface, data, branding, or code.

## Product promise

The network is a place to explore, not just a search result. Open the app and immediately see how buses, regional rail and intercity services connect towns across Southern New England. Essential information remains usable without a network connection.

## Two first-class modes

1. **Explore:** Map-first landing experience; all available routes shown in distinct accessible colors; tap a line to see its identity, agency, stops, timetable, branches, and transfer opportunities; browse by agency, region, and service type; discover reachable destinations and unfamiliar connections.
2. **Travel:** Date/time-aware journey planner with real schedules, feasible transfers, walking/scooter options, last departures, return feasibility, saved itineraries, and explicit data freshness.

## Initial offline acceptance target

Connecticut + PVTA, contingent on acquiring and validating authoritative feed coverage. A successful airplane-mode test must support a locally rendered map, route/stop exploration, schedule browsing, and trip planning without contacting a server. Distinguish planned capabilities from implemented ones.

## Interaction principles

- The map is the default entry point, not an empty origin/destination form.
- Every route has an identifiable label, not color alone.
- Distinguish scheduled, estimated, live, unavailable, and expired information.
- Make it easy to wander the network without first choosing a destination.
- Preserve fast practical routing for users who need to get somewhere.
- Do not imitate any specific third-party product's visual layout or branding.
- Native Android and iOS should share validated offline data packs and consistent network semantics.

## First screen sketch (conceptual)

Full-screen regional network map; compact Explore / Travel switch; filters for agency, bus/rail and coverage; an expandable route detail panel; clear offline and last-updated indicators. This is a proposal, not an implemented UI.
